# ImmortalWrt x86/64 + MT7922「BleachWrt plus 风格」固件

> 目标：在一台 **x86 主机 + MT7922（M.2 PCIe，Wi-Fi 6E）** 上，跑一个功能和闭源固件
> BleachWrt 高大全版（plus）接近、但完全开源可自己重编的 ImmortalWrt。
>
> 基线：`immortalwrt/immortalwrt` master @ `89f1ef18c8`（2026-10-30，25.12 基线，内核 6.18.55）
>
> 本固件：**733 个软件包，squashfs-combined-efi 镜像 314 MB**

---

编译输出在 `bin/targets/x86/64/`：

| 文件 | 说明 |

| `immortalwrt-x86-64-generic-squashfs-combined.img.gz` | 老主板 BIOS/legacy 启动 |
| `immortalwrt-x86-64-generic-ext4-combined-efi.img.gz` | ext4 版（虚拟机/需要可写根文件系统时用） |
| `immortalwrt-x86-64-generic.manifest` | 固件内 733 个包清单，可核对插件 |

sha256（本次构建的 EFI 版）：
`5c27d2714ad57717790950cbdf499594cb94b498b73bc3757c9ade533cc0ee50`

烧写：

- **Rufus / balenaEtcher**：解压 `.img.gz` 得到 `.img`，写 U 盘（7-Zip 某些版本解压会报错，用 Rufus 或系统自带解压）。
- Linux：`gunzip -c xxx.img.gz | sudo dd of=/dev/sdX bs=4M status=progress conv=fsync`
- 虚拟机（PVE/ESXi）：直接导入 `combined-efi.img`，或用 `ext4-combined-efi`。

根分区默认 **2048 MiB**。装完插件/容器后空间紧，用 LuCI「磁盘管理 → 分区扩容（partexp）」扩到盘尾。

## 3. 让 MT7922 无线跑起来

驱动/固件已内置：`kmod-mt7921e`、`kmod-mt7921-common`、`kmod-mt7922-firmware`、
`wpad-openssl`（完整 hostapd）、`wireless-regdb`、`iw-full`、`wifi-scripts`、`rpcd-mod-iwinfo`。

开机后 `lspci` 应看到 MT7922，`ip link` 出现 `phy0`。LuCI 步骤：

1. **网络 → 无线** → 编辑 `radio0`。
2. 先设 **国家/地区代码**（`CN` 或所在地区；**不能留 `00`**，世界域下 6GHz 与部分信道不可用）。
3. 「工作频率」选 `2.4 GHz` / `5 GHz` / `6 GHz`。
4. 「模式」= **接入点 AP**，设 SSID；加密：
   - 2.4G / 5G：`WPA2-PSK` 或 `WPA2/WPA3 混合`
   - **6 GHz：只能 `WPA3-SAE` / `OWE`**（规范如此，脚本会自动把 6G 上的 WPA2 转成 SAE）
5. 保存并应用（`wifi reload`）。

### MT7922 的硬限制（重要）

1. **同一时刻只有一个信道、只能一个 AP**。本版本 mt76 的 `if_limits` 里 AP 接口上限为 1，
   且所有含 AP 的 interface combination 都是 `num_different_channels = 1`。
2. **AP + STA 中继实测不可用（本机 x86 + MT7922 已验证）**：即使把 AP 和上游 Wi-Fi 配成
   完全相同的信道/带宽、WPA2-PSK 正确，只要拉起 STA 接口，MT7922 的 MCU 就挂死——
   `Failed to get patch semaphore` / `chip reset failed` 每 5 秒刷屏，AP 掉到 `Channel: 0`、
   LuCI 卡死、站点列表永远空，**只能物理断电才能恢复**（热重启会变成 `driver own failed`）。
   所以：
   - 「2.4G + 5G + 6G 三个 SSID 同时开」做不到；
   - 「AP + STA 无线中继」**别试**，会搞挂网卡；
   - 想让盒子发 Wi-Fi → **有线 WAN + 纯 AP**；想让盒子自己上网 → **纯 STA**；
     两者都要 → 加第二张网卡。
   → 崩溃恢复步骤、ASPM 硬化、三种方案的配置模板见 [`mt7922-wifi-relay.md`](mt7922-wifi-relay.md)。
3. **6GHz 需要国家码允许**；中国目前未开放 6GHz 给 Wi-Fi，选 `CN` 时 6GHz 不可用（可试 `US`/`JP`，请自行确认法规）。
4. **PCIe ASPM 必须关**：本镜像已在 GRUB 里加 `pcie_aspm.policy=performance`
   （`CONFIG_GRUB_BOOTOPTS`）。注意 `pcie_aspm=off` 只是让内核不改 BIOS 的 ASPM，**不算关**；
   已经装好的机器可在 `/etc/rc.local` 里用 `setpci -s 0000:04:00.0 CAP_EXP+10.w` 清 ASPM 位。
5. 蓝牙：MT7922 的 BT 走内部 USB，已内置 `kmod-btusb`/bluez，命令行 `bluetoothctl` 可用
   （LuCI 没装蓝牙界面；镜像未带 `mt7922bt-firmware`，蓝牙要额外加 linux-firmware 的蓝牙固件）。

### 本版没编进去的（和 BleachWrt plus 的差异）

| 项 | 原因 |
| --- | --- |
| qBittorrent、aMule | 依赖 Qt6 / wxWidgets，其源码站在本机网络下无法稳定下载；网络好的机器加上 `CONFIG_PACKAGE_qbittorrent=y` / `amule=y` 即可 |
| LXC 的 LuCI 界面 | 依赖 `tar` 包，而 x86 上 busybox 已占用该 applet，依赖解不开（LXC 核心已装，可用命令行） |

| iStore 应用商店 | istore feed 的构建时要拉 iStore 前端包，此环境下依赖未满足（可后续手工补齐） |

## 5. 重新编译

### 5.1 本地（WSL2 / Linux，推荐）

> **必须在 Linux 文件系统里编译**（WSL 里放 `~/` 下），不要在 `/mnt/c`、`/mnt/d` 上编，
> 否则大小写不敏感 + 9p 文件系统会导致各种诡异失败。

```bash
git clone https://github.com/yongnianliu/immortalwrt.git
cd immortalwrt
./scripts/build-x86_64-mt7922-plus.sh
```

脚本会自动：装好官方 feeds → 追加 `configs/feeds.plus-ext.conf` 里的 5 个第三方 feed 并只安装
`configs/packages.plus-ext.txt` 白名单 → 打国内网络补丁 → 套用 `configs/x86_64-mt7922-plus.config`
→ `make defconfig` → `make -j$(nproc)`。

几个坑（脚本已处理，手工编时注意）：

1. **不要先跑 `make download`**：这个配置会串行下载*全部*包的源码（包括没选中的），要几个小时；
   直接 `make` 会在编译时按需并行下载。
2. root 编译（Docker/WSL root）要 `export FORCE_UNSAFE_CONFIGURE=1`，否则 GNU tar 等 configure 拒绝运行。
3. **WSL 必须清空 Windows PATH**（`export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin`），
   否则 Windows PATH 里的 `Program Files`（含空格、被转成 `/mnt/c/Program:Files/...`）会让 Go 包的
   `golang-build.sh` 报 `syntax error near unexpected token '('`，所有 Go 包（xray/sing-box/adguardhome…）全编译失败。
4. `scripts/apply-cn-feed-patches.sh` 会关掉 sing-box 的 `naive outbound`（隐藏选项 `def_bool y`），
   否则会拉 `libcronet`（Chrome cronet）→ 需要 gn 工具链 → 墙外下载失败。这个补丁让 feeds 与 config 一致。

### 5.2 GitHub Actions

仓库带了 [`.github/workflows/build-x86_64-mt7922-plus.yml`](../.github/workflows/build-x86_64-mt7922-plus.yml)：
fork 后到 Actions 页点 **Enable workflows**（fork 默认关闭），再 **Run workflow**，跑完从 Artifacts 下载。
（Ubuntu runner 4 核，全量约 2–4 小时。）

### 5.3 改配置

```bash
make menuconfig     # 或直接改 .config
make -j$(nproc)     # 增量编译
```

`configs/x86_64-mt7922-plus.config` 是**本固件实际使用的完整 .config**（10739 行，可直接复用）。
`package/custom/default-settings/` 是首次启动默认值（时区/中文/主题/root 密码）的包。

## 6. 已知问题 / 排错

| 现象 | 处理 |
| --- | --- |
| 没有 `phy0` / 无线页为空 | `dmesg \| grep -i mt79`；确认 `/lib/firmware/mediatek/MT7922*` 存在；确认网卡是 PCIe 版（14c3:0616） |
| 6GHz 看不到 | 国家码还是 `00`，或所选国家不支持 6GHz |
| 开 AP 后掉线 / 扫描异常 | 关 PCIe ASPM：GRUB 加 `pcie_aspm.policy=performance`（本镜像已默认），或 `setpci` 清链路 ASPM 位 |
| **AP 显示 `Channel: 0 (unknown)`、站点列表永远空、LuCI 卡死** | MCU 已挂死（`dmesg` 刷 `Failed to get patch semaphore` / `chip reset failed`）→ **拔电源 20 秒冷启动**，热重启无效 |
| **加了「客户端(STA)」接口就卡死/掉线** | 本卡 AP+STA 并发会搞挂固件，**直接停用 STA 接口**，改有线 WAN 或纯 STA 模式 |
| STA 一直「无线未关联」 | 加密方式要匹配上游（WPA2 用 `psk2`）；别再填 `wpa3-192`/`eap_type` |
| AP 显示「WPA3 OWE」 | 那是**开放网络**（无密码）；改成 `WPA2-PSK` 或 `WPA2/WPA3 混合` 并设密码 |
| docker 空间不足 | 根分区 2GB，partexp 扩容，或把 docker data-root 挪到外挂盘 |
| 多个代理插件互相干扰 | 同一时间只启用一个代理前端（OpenClash/PassWall/PassWall2/SSR+/HomeProxy/Nikki/Momo 选一） |
| 想再精简 | 改 `.config` 去掉不需要的包后重编；或镜像内用 opkg 卸载 |
